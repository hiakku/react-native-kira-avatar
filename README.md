# Kira · Avatar Studio

A separate React Native / Expo app for creating original anime-inspired portrait avatars. This first editor is a working prototype for reviewing the art and experience. It has not been published or monetised.

## Included

- Six hairstyles, four eye expressions, four mouths, six outfits, and six accessory choices (including none).
- Six skin tones, ten hair colours, eight eye colours, eight clothing colours, and six backgrounds.
- Four starter characters, randomise, reset, and undo/redo (up to 60 draft states).
- Saved, named characters and an automatically persisted draft, stored on this device.
- Browser download of a 1024 × 1024 PNG, including optional transparency.
- Native PNG capture and the system share sheet are implemented and require phone testing.
- Phone layout with a sticky portrait while editing; desktop layout with side-by-side preview and controls.
- Original, hand-authored layered SVG artwork. No stock characters, licensed anime characters, generation API, account, backend, or per-image generation cost.

All options are included in the prototype. There are no ads, fake ad rewards, purchases, or analytics. The app currently earns no revenue.

## Run

Use a supported Node release: Node 22.13+ in the Node 22 line, Node 24.3+, or Node 26+.

```sh
npm ci
npm run web -- --port 8082
```

The preview opens at `http://localhost:8082`. It is separate from Cue's source and preview.

For native development, run `npm start` and use an Expo client compatible with SDK 58. If your Expo Go version is incompatible, create a development build. Current native code uses Expo SDK 58, React Native 0.88, Expo Router, react-native-svg, AsyncStorage, react-native-view-shot, and Expo Sharing.

## Check

```sh
npm run check
npx expo-doctor
npx expo export --platform android
```

The last command validates an Android JavaScript/assets bundle; it does not create an installable APK. Lint, TypeScript, and five data/art tests pass. See `VALIDATION.md` for the specific checks and limits.

```sh
npx eas-cli@latest whoami
npx eas-cli@latest init
npm run build:preview
```

Use the user's intended Expo account when linking. The draft Android package is `com.chit20.kiraavatar`. The working brand name and package have not been checked for store availability. Native changes belong in `app.json` or config plugins; native projects are generated by Expo.

Before release, test PNG export/share (including transparency), persistence, Android Back, long collections, and the sticky portrait on physical Android phones.

## Data and saves

Draft changes persist automatically. “Save character” creates a named snapshot; reopening one makes it the editable draft. Saving again creates a new version, preserving the earlier snapshot. Saved characters survive ordinary app restarts. Undo history is session-only. Saved removal asks for confirmation. A storage failure shows an error and a retry action; corrupt data is not replaced by an empty collection.

Clearing browser/app data or uninstalling removes the collection. PNGs are image exports, not editable project backups. Export favourite images before removing app data. Data is not encrypted by this app. Production code has no cloud sync or telemetry; development mode connects to the development server.

## Monetisation follow-up

The proposed model is free core creation/export, with optional rewarded ads for future original accessory/outfit packs. Live ads require an ad-provider account and approval, consent/audience configuration, and a supported distribution path. Use test ad IDs during development. The current art options are fully available and there is no pretend “watch ad” flow.

AdMob does not currently list Indus among its supported stores; Indus-only distribution would limit AdMob readiness/serving. Confirm provider eligibility for the chosen store before adding a dependency on ad income. Store reach and competitor installs do not establish this app's revenue potential.

## Source

- `src/app/`: editor and collection routes, root provider layout.
- `src/art.ts`: original layered vector renderer shared by preview and web export.
- `src/model.ts`: catalogues, presets, randomisation, storage validation.
- `src/store.tsx`: draft history, collection, persistence.
- `src/export.ts`: actual PNG download and native share.
- `src/ui.tsx`: shared controls, responsive styles, dialogs.

The artwork currently has one portrait/body base with six variations per major clothing/hair category. Expanding the art catalogue and testing whether people return are future work.

## Refined portrait style

The original flat character art has been replaced with more natural face proportions, smaller almond eyes with detailed irises, softer palette-relative skin shading, shaped noses and lips, fine hair strands, dimensional clothing, and finer jewellery. Existing saved characters use the new renderer automatically and keep their choices. Preview, thumbnails, and PNG export share the same artwork and tighter framing.

A separate high-detail image-generation reference and its final prompt are saved under `assets/art-direction/`. The reference is not displayed as the editable avatar: the app's layered illustration remains less textured than that raster reference. No generation service is called by the app.

## Website deployment

Public website: https://hiakku-kira-avatar.pages.dev/

Build with Node 22.13+ and deploy the compiled website to Cloudflare Pages:

```sh
npm run build:web
npx wrangler@4.160.1 pages deploy dist --project-name hiakku-kira-avatar --branch main
```

The post-export script moves Expo dependency assets out of `assets/node_modules/` because Cloudflare excludes directories with that name. Only compiled website assets are uploaded. This is a direct upload deployment; GitHub pushes do not automatically redeploy it.
